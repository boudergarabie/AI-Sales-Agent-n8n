# Setup guide

This guide explains how to configure the exported n8n workflows on your own n8n instance, including an n8n instance hosted on a VPS.

## Requirements

- An n8n instance reachable over HTTPS.
- PostgreSQL and Redis.
- A Supabase project with the pgvector extension available.
- A Google account and a Google Cloud project for Google Sheets OAuth2.
- A Meta developer app and a Facebook Page with Messenger access.
- A Telegram bot created with @BotFather.
- API accounts/keys for OpenRouter, Groq, OpenAI, ElevenLabs and imgbb (imgbb is used only by workflow 08).

## 1. Prepare the Google Sheets workbook

1. Open `data/All_Sheets .xlsx` and import it into Google Sheets, or upload it to Google Drive and open it with Google Sheets.
2. Keep these five tab names exactly as provided: `Products`, `Inventory`, `Orders`, `Yalidine_Tarifs` and `Bot_Control`.
3. Keep the existing column headers unchanged. The workflows refer to these sheet names and fields.
4. Copy the spreadsheet ID from its URL. It is the value between `/d/` and `/edit`.
5. Replace `YOUR_GOOGLE_SHEET_ID` in the relevant workflow nodes with this ID.

## 2. Configure Google Sheets OAuth2 in n8n

The project uses **Google Sheets OAuth2 credentials (Client ID and Client Secret)**. It does not require a Google Service Account.

1. In Google Cloud Console, create or select a project.
2. Configure the OAuth consent screen and enable the Google Sheets API. Enable Google Drive API as well if required by the credential flow or file picker.
3. Create an OAuth Client ID. For an n8n VPS deployment, choose the application type and redirect configuration supported by your n8n Google OAuth credential.
4. In n8n, create a Google Sheets OAuth2 credential and copy the OAuth Redirect URL shown by n8n.
5. Add that exact redirect URL to the authorized redirect URIs of your Google OAuth client in Google Cloud Console.
6. Copy the Client ID and Client Secret from Google Cloud into the n8n credential, save it and complete the Google authorization flow.
7. Select this credential in every Google Sheets node and Google Sheets Tool node in workflows 01, 02, 04, 05, 06 and 08.

For a VPS, make sure n8n's public base URL is configured correctly (including HTTPS) so the redirect URL generated by n8n uses your real public domain. Do not guess or manually invent the redirect URL; copy the exact URL displayed in the credential.

## 3. Prepare databases and Supabase

- Configure PostgreSQL and Redis connection credentials in n8n.
- Create a Supabase project and configure the Supabase credential used by the vector-store nodes.
- Configure the OpenAI credential used by the embeddings nodes.
- The repository does not include SQL initialization files. Check the table and vector-store requirements in the imported nodes and create the required database structures in your own PostgreSQL/Supabase projects before running the related workflows.

## 4. Create the remaining n8n credentials

Create the credentials required by the nodes, then select them after importing the workflows:

- OpenRouter API access.
- Groq API access.
- OpenAI API access for embeddings.
- ElevenLabs API access.
- Telegram bot credentials.
- PostgreSQL and Redis credentials.
- Supabase API credentials.
- HTTP authentication credentials used by the HTTP Request nodes for external APIs.
- Google Sheets OAuth2 credentials from step 2.

Some HTTP Request nodes use authentication headers or query parameters directly. Inspect those nodes and configure the authentication values they expect. Do not paste live secrets into files that will be committed to GitHub.

## 5. Import the workflows

Import the JSON files from `workflows/`. Import the called workflows before the workflows that call them. After import:

1. Open each workflow and resolve credential warnings.
2. Search the workflow nodes for `YOUR_` and replace every placeholder with your own values.
3. In Execute Workflow nodes, select the correct imported target workflow.
4. Configure the error workflow (workflow 07) in the workflow settings where appropriate.
5. Check node references, sheet names, table names, API endpoints and model settings.

The placeholders currently present in the exports include the Google Sheet ID, Facebook Page ID and Page access token, Telegram chat ID, ElevenLabs voice ID, imgbb API key and called-workflow IDs. See `.env.example` for the checklist.

## 6. Configure the knowledge base

Open workflow 03. Review and replace the example store-policy content in the workflow with your own policies, then run the workflow to load the content into Supabase. Confirm that the Supabase vector-store nodes and OpenAI embeddings credential are connected correctly.

## 7. Configure Meta Messenger

1. Configure your Meta app and Facebook Page for Messenger Platform access.
2. Set the webhook callback URL to your n8n production webhook URL. The workflow's webhook path is `ai-sales-agent`, so the URL normally follows `https://YOUR_N8N_DOMAIN/webhook/ai-sales-agent`.
3. Configure the required verification token and subscribe the Page to the message events required by the workflow.
4. Replace the Page ID and Page access token placeholders in workflow 02.
5. Test receiving and sending messages before activating the workflow for customers.

Follow Meta's current Messenger Platform documentation for app review, permissions and webhook subscription requirements.

## 8. Configure Telegram and scheduled workflows

- Add your Telegram bot credential to the Telegram nodes.
- Replace `YOUR_TELEGRAM_CHAT_ID` with the chat ID that should receive owner alerts.
- Configure workflow 06's schedule and confirm the pause/reactivation duration matches your intended behavior.
- Test the ON/OFF buttons in workflow 05.

## 9. Test before going live

Test at least the following with a test Page/customer and sample spreadsheet data:

- Text messages and rapid consecutive messages.
- Voice notes, images and videos.
- Product lookup and stock availability.
- Delivery fee lookup.
- Order confirmation and stock reservation.
- Human handoff and Telegram notification.
- Bot pause, manual reactivation and automatic reactivation.
- Error notification and logging.
- Workflow 08 image generation, if you intend to use it.

Do not activate the system for real customers until credentials, permissions, database structures, webhook behavior and order handling have been verified.
